# Auditoría de fiabilidad — 2026-09-06

Punto de partida: `f7eba6c`, `main` sincronizado con origin antes de editar.
La auditoría usa fixtures offline; no controla el host ni lanza un compositor real.

## Fallos reproducidos y corregidos

| Caso | Antes | Corrección y regresión |
| --- | --- | --- |
| Respuesta IPC a cuentagotas | Cada lectura renovaba 3 s; el test superaba 4,5 s sin finalizar | Socket no bloqueante y presupuesto monotónico único para conexión/envío/respuesta; `tests/ipc.py` |
| Cancelación en IPC sin respuesta | `SIGTERM` no acababa en 1 s; `EINTR` volvía a esperar | Poll en intervalos de hasta 50 ms con comprobación de cancelación; `tests/ipc.py` |
| Timestamp externo extremo | `minInt(i64)` desbordaba la resta y abortaba sin JSON en ReleaseSafe | Rechazo previo de timestamps negativos; unitarias de geometría e integración |
| Visor ignora SIGTERM | Padre y reglas temporales quedaban pendientes más de 3 s | Gracia limitada, escalada para el hijo propio y limpieza IPC no cancelable con presupuesto de 250 ms; `tests/preview.py` |
| Helper ignora SIGTERM | `Child.kill` de Zig 0.16 usa TERM + wait, insuficiente como escalada | Limpieza compartida TERM → KILL → recolección; regresión adicional de captura |

La función compartida solo admite `std.process.Child` directos aún no recolectados.
No reemplaza la atribución de árboles de sesiones. Un proceso bloqueado en el
kernel puede demorar su recolección incluso tras SIGKILL: no es una garantía de
tiempo real frente a fallos del kernel.

Además, la lectura del token dentro de `Runtime.guard` usa ahora la arena temporal
de cada comprobación; antes acumulaba asignaciones en la arena de la acción.
Esta mejora se identificó por inspección, sin una afirmación de ahorro medido.

## Verificación reproducible

```sh
zig build check -Doptimize=ReleaseSafe
zig build test
python3 tests/keyboard_unit.py
zig build pip -Doptimize=ReleaseSafe
```

Las regresiones nuevas de IPC, timestamp y cierre del visor se ejecutaron primero
contra el comportamiento anterior y fallaron. Se conserva una prueba positiva
de respuesta IPC fragmentada para evitar rechazar comunicaciones válidas.
Las pruebas no acreditan equivalencia visual ni rendimiento de una sesión real.

Resultado local: `check` pasó 27 unitarias Zig y 107 pruebas Python (134 en total).
También pasaron las 27 unitarias en Debug, las 9 del runner aislado de teclado
y la compilación ReleaseSafe del PiP. `readelf` confirmó que la CLI no enlaza GTK.
El formato Zig, la compilación sintáctica de Python y Bash también pasaron.
